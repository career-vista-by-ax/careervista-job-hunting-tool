# Focused company investigation

Open a job's Company research disclosure, approve a topic and selected source URLs, then use your browser agent or add a report manually. Supported topics are benefits, salary, interviews and workplace conditions. No source is fetched by the app. Accessible Glassdoor reports and other sources use the same evidence interface; login, paywalls, blocked access and missing reports never become invented answers.

Public API: `GET /api/v1/jobs/:id/company`; POST its `/requests`, `/reports`, `/summaries`, `/access` subresources. See the exported input interfaces in `src/company.ts`. Every mutation requires an operationId; identical retries preserve the record and changed retries fail. Job deletion and ordinary backups/exports include this history. Original reports are retained before agent summaries.

A request selects topics and 1–20 HTTP(S) sources. A report must use a selected source origin and requested topic, identify the named company, mark linkage confirmed/uncertain/mismatch, explain that judgement, retain author/team/time context, original readable text and an exact supporting quote. Attribution is either employer_claim or external_report. Different company names, cities and industries require investigation; matching a company name alone is insufficient. Incorrect company reports stay visible as mismatches and cannot support a summary. Conflicting reports are retained side by side, never merged into a culture verdict.

Summaries are always labelled model_inference, require saved report IDs from the request, actual agent context (model/provider only when known) and explicit unknowns. Uncertain company linkage requires at least one unknown. This validates provenance, not the truth of model prose: the user reviews the explanation and originals. Never call an anecdote or promotional statement a verified culture fact.

The agent records authentication or verification with an opaque host sessionRef, pauses, and lets the user complete the website interaction. A resumed event requires the same reference and explicit userConfirmed. Capture is blocked while paused. No password/cookie fields or raw failure pages are accepted. Unsupported/unavailable events remain visible; manual entry remains available under a new approved request. The host owns session persistence and credentials. For paid agent work, use the Research Run budget reservation/authorization interface before calls; CareerVista does not control unrelated host spending.
