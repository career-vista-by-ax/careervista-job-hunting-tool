# Reassess saved evidence

Reassess saved jobs selects any persisted jobs, including excluded jobs, an approved profile revision and one of its tracks. Set an explicit batch spending budget and conservative per-job estimate. No website navigation or model SDK is built in; any compatible agent can consume the public JSON handoff. The batch reserves the full selected estimate before work. The agent host owns actual billing and unrelated spending.

POST `/api/v1/reassessments` with `{requestId,profileVersion,trackId,jobIds,budget:{amount,currency},estimatePerJob}`. GET the collection or `/:id` for progress. POST `/:id/jobs/:jobId/input` with `{operationId}` before model work. This authorizes one item and returns the exact saved observation IDs/text, approved profile/effective preferences, earlier assessment and boundaries. Identical authorization can recover interrupted work. Complete items are not authorized again.

POST `/:id/jobs/:jobId/result` with `{operationId,outcome,actualCost,assessment?}`. Outcomes: assessed, insufficient_evidence, provider_failure, malformed_output. `actualCost:null` retains the conservative estimate and marks actual unavailable. Assessed requires a new valid AssessmentInput with the selected job/profile/track and complete observation snapshot. It appends a new assessment; previous evidence, reasoning and model context remain immutable. Failures create no label and never become definite mismatches. Actual costs beyond budget block further authorizations. Changed content needs a new batch; exact retries do not duplicate history or charge twice.

After a changed hard requirement is approved, select previously excluded jobs and reassess from cache before another collection session. A new non-excluded latest assessment restores eligibility without deleting the earlier exclusion. Review decisions and application records are independent and unchanged. Permanently deleted jobs cascade out of batches; historical selected/deleted counts and committed costs remain. Private backups/exports preserve batches and all assessment history.

Deterministic public-interface tests cover revised hard-to-soft preferences, preserved exclusion/model context, restored eligibility, insufficient evidence/provider failures, explicit budget exhaustion, retries, application/review independence and backup/restart. These fixtures do not establish model quality; real Codex evaluations are recorded separately.
